# Dashboard Surface Brief

## Scope and mode

- Primary target: `app/(app)/dashboard/page.tsx`
- Mode: Operate
- This is the first expression of **The Compact Portfolio Workspace** direction.

## Audience, job, and success

PMO Officers use the Dashboard to inspect honest KRA/KPI definitions and act on the latest Progress and Bump activity. Success means the portfolio measures, current activity, and next useful action are legible within seconds in a calm, dense workspace.

## Approved composition

Use the **Compact Portfolio Workspace** composition. Place three equal, warm-neutral KPI definition instruments across the top. Below, place Latest Progress as a wider dense record area and Latest Bumps as a tighter companion rail; both extend to the bottom of the desktop work area.

The Dashboard has no greeting hero, attention queue, or Ball module. Those concerns remain available in dedicated views and project records.

A visible Bump control retains the written label and original sculpted 3D fist as the one playful signature element on this surface.

## Memorable moment and motion

The Bump control is the memorable object. It may anticipate slightly, then complete one quick contact-and-rebound cycle. Do not loop the animation. Under `prefers-reduced-motion`, use an immediate state change or brief cross-fade with complete written confirmation.

## Constraints

- Preserve the real Dashboard content and never invent KPI results.
- Keep actionable records visible in the first viewport on common laptop sizes.
- Project rows preserve Code, name with State/Priority, Stage, Ball Owner, and held duration.
- Use regular rectangular or softly rounded KRA/KPI panels; no skewed, clipped, polygonal, or novelty-shaped cards.
- Use one violet accent plus warm and dark neutrals; semantic status colors remain small and always accompanied by text.
- Keep interface surfaces flat: use borders, spacing, and color instead of cast shadows, contact edges, or hover lifts.
- Dimensional objects never replace labels, familiar controls, status text, or navigation icons.
- Mobile linearizes KPI definitions, then Progress, then Bumps.

## Open implementation decisions

- Final type families and exact palette values require live rendering and accessibility testing.
- Verify the compact three-KPI row remains readable with real and localized copy.
